The problem

An RIA must give suitable, source-backed advice fast. LLM chat can't be trusted with numbers: NAVs get invented, guarantees slip in, nothing is reproducible.

The fix

Facts are commits. Gates are CI. The LLM never writes a number — the vault and deterministic calculators do. Approval is a hash.

The loop (live demo)

  • Pick persona → facts seed as commits (sha256-chained)
  • Deterministic planner: SIPs, emergency gap, drawdowns, risk clamp
  • 9 gates re-run on every commit — the domino
  • Slot-filled draft passes numeric + banned-phrase lint
  • Adviser approves → sha256 fingerprint → read-only client view
  • Any fact edit → new commit → approval auto-revoked

Invariants, enforced

  • I1 LLM never emits material numbers — slots only; lint fails on raw digits
  • I2 Every claim has a source ({doc,quote}/URL) or says "unavailable"
  • I3 No guaranteed/assured/risk-free language (banned-phrase lint, incl. Hinglish)
  • I4 Client output only under approval bound to content hash
  • I5 Retrieved docs/tools are data, never instructions · I6 no secrets in repo · I7 pnpm repro regenerates every report number

Architecture

Layer A — research chat

Own OpenAI-compatible client (fetch+SSE) → 3 providers, 13 probed models, EWMA routing + hedging + failover → tool loop (web/calc/files/vault) → streamed cited answers + live workbench.

Layer B — Plan PR

Case repo (hash-chained commits) → planner (risk capacity vs tolerance, clamp) → gates → slot draft → approval fingerprint → client view.
